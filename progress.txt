# DeckPVP Progress Log
Started: Mon Mar 16 2026

## Codebase Patterns
- Card definitions in `packages/shared/src/cards.ts` are shared references — clone cards (structuredClone or spread) when building player decks
- `STARTER_DECKS[classId]` returns the starter deck array for any ClassId
- Use `pnpm --filter @deck-pvp/<package>` to run commands in a specific package
- Shared package is referenced via `workspace:*` and imported as `@deck-pvp/shared`
- Client uses Vite + React 19 + Tailwind v4 (`@tailwindcss/vite` plugin) + PixiJS v8
- Server uses tsx for dev (watch mode), Express + Socket.io
- TypeScript strict mode is enabled via `tsconfig.base.json` at root
- Root `pnpm dev` starts client and server concurrently with `--parallel -r`
- Client on port 5173, server on port 3001
- GameBoard uses layered architecture: PixiJS canvas (absolute, bottom) + React HUD overlay (absolute, top with pointer-events-none/auto)
- BattlefieldCanvas exposes animation methods via `forwardRef` + `useImperativeHandle` (animateAttack, animateBlock, animateBuff)
- Manual particle system: array of `{gfx, vx, vy, life, maxLife}` objects updated each frame in the main ticker loop
- `lastAction` field on GameState/ClientGameState tracks the most recent card play for opponent animation sync
- Card play animation CSS: `isPlaying` prop triggers translate-y + scale + opacity transition on the React card element
- Turn transition events: `TurnEvent[]` on GameState communicates what happened during endTurn (poison, orbs, reshuffle) — client animates with staggered delays
- Discard animation: delay server emit by ~450ms after setting `isDiscarding` state so CSS animation completes first
- PixiJS v8 `Application.init()` is async — use a `destroyed` flag to handle unmount-during-init cleanup
- GameEngine is the authoritative game logic class in `packages/server/src/GameEngine.ts`
- GameEngine stores games in a Map keyed by gameId — use `engine.getGame(id)` to retrieve
- Server tests use vitest — run with `pnpm --filter @deck-pvp/server test`
- Socket event types (`ClientToServerEvents`, `ServerToClientEvents`) are in shared types — use for typed Socket.io on both client and server
- `ClientGameState` is the sanitized game state sent to each player (opponent hand hidden, only counts sent)
- Client socket wrapper is in `packages/client/src/socket.ts` — functions return unsubscribe callbacks for React cleanup
- Server tracks player→game mapping in `playerGames` Map and handles disconnect cleanup (awards win to remaining player)
- Class-specific HP values are in GameEngine's `CLASS_HP` constant (warrior=75, rogue=65, mage=60)
